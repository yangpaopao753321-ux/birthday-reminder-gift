## 2026-09-23 更新：定时任务架构从"一人两任务"改为"月度扫描"（执行人：豆包）

- 背景：使用者反馈一人两任务在人数多时（100人=200个任务）任务列表爆炸，要求合并。
- 变更：
  - `references/workflow.md` §2：开年任务不再逐人建一次性提醒子任务，改为建1个每月1号10:30的扫描任务；写回时重置 `gift_reminded_year`。
  - `references/workflow.md` §3：从"单人提醒触发"重写为"月度扫描+命中推送"——读全量画像，筛选 0≤days_left≤60 且今年未推过的人，分三档（当天/1-15天/16-60天）推送，推完打 `gift_reminded_year` 去重标记。
  - `references/data-schema.md`：新增 `gift_reminded_year` 字段（去重标记，开年重置）。
  - `SKILL.md` description：同步更新为"每月1日扫描未来60天，去重每人每年只推一次"。
  - 定时任务：删除旧的一人两任务（用户A/用户B/用户C 各前30天+当天）；新建「生日月度扫描」（每月1号10:30 cron）；开年逻辑合并进该任务。
- 设计权衡：放弃"精确第30天弹提醒"的仪式感，换取任务数从 2N 降到 2（1开年+1月度），触发次数从 200 降到 13/年；空跑概率低（每月窗口内大概率有人生日）。
- 未变更：画像 JSON 结构（仅加1字段）、农历换算、礼物双层检索逻辑、双通道推送。

## 2026-09-23 更新：加 ReAct 执行纪律与检测基准（执行人：豆包）

- 背景：使用者要求加硬约束，防止 AI 执行时跳步、编造日期、双通道失败还打去重标记等错误。
- 变更：
  - `workflow.md` 新增「ReAct 执行纪律（强制，不可跳过）」章节：要求思考→行动→观察循环，禁止一口气跑完。
  - 5 个检测基准：①画像文件可读 ②当年数据完整 ③days_left 可复现 ④去重标记正确 ⑤推送通道与写回（至少一个通道成功才允许打 gift_reminded_year）。
  - 反模式清单：禁止脑补生日/爱好、禁止双通道失败还打标记、禁止凭模型记忆算日期。
  - 通用纪律补一条：日期锚点必须来自系统时间。

## 设计要点备忘

- 数据与逻辑分离：画像 JSON 为唯一事实来源，定时任务 query 只写执行指引。
- 打包分发只发框架；`sample-profile.json` 为脱敏示例，`project-log.md` 分发前删除。
- 核心机制：每月1号扫描未来60天，去重每人每年只推一次；开年逻辑合并进同一任务。
- 推送通道与小红书登录态为使用者环境依赖。
