# 农历 → 公历换算方法

生日默认记录农历，每年公历日期不同，开年任务必须逐人换算。支持 1900–2100 年，含闰月处理。

## 换算目标

- **当年公历生日**：农历年（当年）+ `lunar_birthday`（+ 闰月）→ `YYYY-MM-DD`，写入 `annual_birthday`。
- **出生年公历日期**：出生年 + `lunar_birthday` → 公历月日，用于推算 `zodiac_sign`（终身不变）。

## 执行顺序（按可靠性优先）

1. **本地脚本**：运行 `scripts/lunar_conversion.py <lunar_year> <lunar_month> <lunar_day> [--leap]`。
   - 脚本优先尝试已安装的农历库（lunardate / sxtwl / lunar_python），可离线秒级换算。
   - 若库不可用，脚本输出明确提示，进入下一步兜底。
2. **万年历检索**：用通用搜索查询「{农历年}年农历{月}{日}是公历几月几日」（闰月加「闰」字），从结果中取公历日期。
   - 两个独立来源（如两个网站/页面）结果一致才采信；不一致则再查一次，仍不一致向使用者说明。
3. **人工确认**：检索结果与使用者认知（如「我妈生日每年都是国庆节前后」）冲突时，以使用者确认为准。

## 关键边界

| 边界 | 处理 |
|---|---|
| 闰月（如闰四月） | 画像 `lunar_leap_month=true` 表示过闰月那天；换算结果与普通月不同，务必核对 |
| 农历 12 月 / 正月生日 | 换算后公历可能跨年（如农历腊月二十 → 次年 1 月），`annual_birthday` 年份按公历年份记录 |
| 2 月 29 日等效（农历生日无此问题） | 农历无固定 2/29，无需处理；公历扩展字段若遇 2/29 且当年非闰年，按 2/28 或 3/1 与使用者确认 |
| 年份边界（1900/2100） | 超出脚本与万年历支持范围时，明确告知使用者无法可靠换算 |

## 开年任务中的校验

- 换算完成后，抽查前一年 `annual_birthday` 记录与今年结果，确认农历年递增后日期漂移合理（通常前后 ±20 天内，闰月例外）。
- 每人换算结果写入画像前，与使用者上一年确认过的生日记录对比，异常（漂移过大）先核实再写入。
